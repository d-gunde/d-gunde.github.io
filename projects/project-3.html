Automating a Secure AWS Client VPN With Terraform

Professional Project · Cloud Infrastructure · Published on DEV Community, August 2024

Read the full article on DEV

The setup described in the article.

Overview

A technical article I wrote and published on DEV Community about automating an AWS Client VPN with Terraform, so that a private Amazon MWAA (Apache Airflow) environment can only be reached through a secure, certificate-based connection.

The Problem

Our MWAA environment was set to private access, which meant users needed a VPN to reach the Airflow web interface. Creating a Client VPN endpoint and its supporting pieces by hand is slow and easy to get wrong, and the same steps have to be repeated for every environment.

My Approach

  1. Set up certificates. I imported the server and client certificates into AWS Certificate Manager with the AWS CLI, for mutual certificate authentication.
  2. Defined the VPN endpoint in Terraform. An aws_cloudformation_stack resource creates the AWS::EC2::ClientVpnEndpoint, with the certificate ARNs read from aws_acm_certificate data sources.
  3. Connected it to the private network. aws_ec2_client_vpn_network_association links the endpoint to the private subnet where MWAA runs.
  4. Controlled access. aws_ec2_client_vpn_authorization_rule grants access to the VPC’s address range.
  5. Made it reusable. Region, VPC, subnets, security group and client address range are variables set in terraform.tfvars, so each environment is one terraform apply away.
  6. Documented the user side. The article shows how to download the client configuration, add the certificate and key to the .ovpn file, and connect with the AWS VPN client.

Tools and Technologies

Terraform AWS Client VPN Certificate Manager Amazon VPC AWS CloudFormation Amazon MWAA AWS CLI

Impact

Turned a long, manual setup into a repeatable Terraform deployment, so every environment gets the same secure VPN configuration, with less manual work and infrastructure that is easier to update and maintain.

Connection to AI

AI and data pipelines often run on sensitive data, and the tools that orchestrate them should not be open to the internet. Keeping orchestration like Airflow behind private, certificate-based access is part of the security foundation that responsible AI systems rely on.
