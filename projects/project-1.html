dbt Cloud Artifacts Pipeline

Professional Project · Data Engineering

Simplified architecture. Names and internal details are generalized.

Overview

An event-driven pipeline that automatically saves dbt Cloud job artifacts in AWS after every scheduled run. It gives the data team a lasting record of which models ran, which tests passed or failed, and how models depend on each other, without anyone downloading files by hand.

The Problem

Our dbt jobs were started on a schedule from AWS, but once a job finished, AWS had no built-in way to know it was done. The run results, test outcomes, and lineage metadata stayed inside dbt Cloud, which made it hard to monitor runs over time or investigate failures later.

My Approach

  1. Scheduled trigger. An AWS Step Functions workflow runs on a schedule and calls a Lambda function that starts the dbt Cloud job.
  2. Event-driven completion. Instead of polling dbt Cloud to check whether the job was done, I set up a dbt Cloud webhook that fires when the job completes.
  3. Artifact capture. The webhook triggers a second Lambda function, which fetches the job's artifacts and stores them in AWS for monitoring and analysis.
  4. Infrastructure as code. All AWS resources are defined and deployed with Terraform, so the setup is consistent and repeatable across environments.

Tools and Technologies

dbt Cloud AWS Lambda AWS Step Functions Webhooks Terraform Python

Impact

Every scheduled dbt run is now recorded automatically, so the team can track run history, spot failed tests quickly, and trace lineage without manual work.

Connection to AI

Machine learning models are only as reliable as the data that feeds them. Knowing exactly which transformations ran, which data quality tests passed, and where each table came from is the kind of observability and lineage that trustworthy AI depends on. This project is the foundation work that lets teams answer "can we trust this data?" before a model is trained on it.
