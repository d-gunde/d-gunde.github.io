Data Request Helper: An AI Intake Assistant for Analytics Teams

AIML-500 · Workshop 1 · AI Lab · October 2026

Try the chatbot

Introduction

Every analytics team knows this message: "Can I get the sales numbers?" It looks simple, but it leaves out what the data is for, which time period, which calendar, and who will use it. The analytics engineer then spends days going back and forth, and sometimes builds the wrong thing. I built an AI assistant that fixes this at the start, before any work begins.

Description

The Data Request Helper is a working chatbot built on Chatbase. A business user describes what they need in plain words, and the bot asks short follow-up questions, one at a time, starting with why they need the data. When it has everything, it produces a clean Data Request Summary the user can send straight to the analytics team. It explains data terms in simple language, refuses personal information, and never promises deadlines.

On this page you will find the design process, the test results, before-and-after fixes, and the full bot instructions, which you can reuse for your own team.

Objective

I wanted to show how generative AI can solve a real, everyday problem in data work, not just answer questions. My goal was to use design thinking to build an assistant that business users would actually find easier than a form, and that analytics teams could trust to collect complete requests.

Process

I followed the five phases of design thinking.

  1. Empathize. I started from my own experience. On a demand planning project for a retail client, our data feeds did not match the business team's reports because we used a different fiscal calendar, a detail no one had asked about at the start. I also analyzed a sample of 40 data requests with ChatGPT's Data Analyst GPT:
    2.9×longer delivery for incomplete requests (7.05 vs. 2.41 days)
    10×more follow-up questions (4.38 vs. 0.42)
    57% vs. 0%of requests needing rework

    Sample data was fictional, created for this exercise.

  2. Define. How might we help non-technical business users describe their data needs clearly, so analytics teams can deliver the right data faster with fewer follow-up questions?
  3. Ideate. I compared a longer request form, a template document, an AI that builds reports automatically, and a conversational assistant. The assistant scored highest on impact, feasibility, and user value, because a conversation adapts to each request and asks for the purpose first.
  4. Prototype. I wrote the bot's instructions (an 8-step flow, a summary format, and rules), added a knowledge source with a request checklist and plain-language definitions, and set a custom welcome message. I did not upload any real data.
  5. Test and iterate. I ran 10 test scenarios, found two gaps, changed the instructions, and retested until every scenario passed.

Before and after: two fixes

Privacy wording. The first version opened with "Thanks for sharing" when a user pasted a customer email. I added a rule to lead with a clear privacy message instead.

No repeat questions. When a user wrote "fiscal 2026," the bot still asked which calendar to use. I added a rule to confirm details the user already gave instead of asking again.

Value Proposition

This assistant gives analytics teams a ready-to-use way to collect complete data requests the first time, cutting back-and-forth, rework, and mismatched numbers, while giving business users a friendly way to ask for data without knowing technical terms.

Unique Value

Most chatbot demos are built by people looking at the problem from the outside. I built this one from the inside: I am the analytics engineer who receives these requests. That is why the bot asks about the fiscal calendar, a detail that broke a real project for me, and why it starts with business purpose rather than technical fields. It is also designed responsibly from the start, with no real data, a refusal of personal information, and no promises it cannot keep.

Relevance

Any team that handles data requests can use this pattern, whether they work in a ticketing tool, a Slack channel, or a shared inbox. The instructions below can be adapted for other intake processes, such as dashboard change requests or data access requests. It also shows a practical, low-risk first step for bringing AI into a workplace: start with a narrow, well-defined task and test it carefully.

View the bot's instructions (reuse and adapt them) 
You are the Data Request Helper. You help business users write clear, complete data
requests for an analytics team. Use simple, friendly language and ask ONE question at a time.

Ask these in order, skipping any the user already answered:
1. Business purpose
2. Metric needed
3. Time period
4. Fiscal or standard calendar
5. Filters or breakdowns (region, product, store)
6. Who will use it and how
7. Format: dashboard, report, or data extract
8. Deadline and why

Then show a DATA REQUEST SUMMARY with all 8 items and ask "Does this look correct?"
Fix only the parts the user corrects.

Rules:
- Never accept personal data like names, emails, or passwords. If shared, start with
  "For privacy, please do not share personal details." Do not thank them for sharing it.
- If the user already states the calendar type, do not ask again. Confirm it in the summary.
- Never promise deadlines or confirm data exists. Do not write SQL.
- Politely redirect off-topic questions.
- If unsure about a definition, tell the user to confirm with the analytics team.
